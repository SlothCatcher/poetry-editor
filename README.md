# Строка — редактор стихов

Веб-приложение на React, React-Bootstrap и Vite. Деление русских слов на слоги — библиотека `syllables-ru`.

## Запуск

```sh
npm install
npm run dev
```

Откройте адрес, напечатанный Vite. Для сборки: `npm run build`.

Для серверного анализа рифм отдельно запустите сервис из соседнего репозитория [`stroka-rhyme-server`](../stroka-rhyme-server/README.md) по его инструкции. Без него доступен локальный анализ в браузере. По умолчанию Vite проксирует `/api` на `http://127.0.0.1:8002`; адрес сервиса можно изменить, задав переменную окружения `RHYME_API_URL` перед запуском Vite:

```sh
RHYME_API_URL=http://127.0.0.1:8002 npm run dev
```

Для статической production-сборки настройте проксирование `/api` на сервис на веб-сервере. В браузерном коде адрес сервиса не используется напрямую. Для публичного развёртывания сервиса необходимы аутентификация, ограничение запросов и HTTPS.
## Возможности

- Создание, редактирование и удаление стихотворений; экспорт текущего стихотворения в TXT.
- «Импорт .txt» добавляет один или несколько файлов как отдельные стихи, не заменяя существующие. Поддерживаются текстовые файлы UTF-8, в том числе экспорт Samsung Notes как в примере: строки и пустые строки сохраняются. Для файлов вида `Notes_YYMMDD_HHMMSS.txt` название берётся из первой непустой строки, которая также остаётся в тексте; в остальных случаях — из имени файла. Максимум 2 МБ на файл. При включённой синхронизации импортированные стихи также отправляются на Google Диск.
- Текстовый режим: число русских гласных (слогов) справа от каждой строки. Пустые строки не учитываются в общем количестве строк, а счётчик слогов для них не отображается. Длинные строки не переносятся, их можно прокручивать по горизонтали.
- Автоматическая расстановка ударений кнопкой «Расставить автоматически»: библиотека `@roj/rustress` использует словарь и модель ONNX, работа выполняется в браузере. Модель загружается при первом нажатии; ранее расставленные ударения в словах сохраняются. Результат может содержать ошибки, в том числе в омографах, и его следует проверить. Если текст изменился во время обработки, результат не применяется. После обработки открывается форма с оставшимися без отметки словами: в контексте показаны варианты ударения, «Оставить без ударения» запоминает выбор, «Пропустить» не запоминает. Повторяющиеся словоформы показываются один раз: выбор применяется ко всем их вхождениям. Библиотека не отдаёт оценки уверенности, поэтому список определяется по отсутствию ударения, а не по достоверному уровню уверенности; односимвольные слова и словоформы с уже сохранённым ручным выбором исключаются.
- Ручная постановка ударения: установите курсор сразу после русской гласной и нажмите **Ctrl + Enter** или кнопку «Ударение». Повторное нажатие снимает метку. Ударение отображается и хранится как диакритический знак U+0301 над гласной и включается в TXT. Обратный апостроф после русской гласной автоматически преобразуется в этот знак, в том числе в ранее сохранённых текстах.
- Ручной выбор ударения запоминается отдельно для каждого стихотворения и применяется ко всем совпадающим словоформам без учёта регистра, включая новые завершённые слова. Другая форма слова и написание через е/ё считаются отдельными словами. Повторное снятие ударения снимает его у всех совпадений и сохраняет этот выбор, в том числе при автоматической обработке. Это может быть неверно для омографов с разными значениями.
- Режим сетки: по клетке на слог; ударные клетки подсвечены. Редактирование — в текстовом режиме. Переключатель «Рифмы» включает приблизительный поиск как внутри строк, так и на их концах. Подсвечиваются слоги от ударного до конца найденного слова или сочетания. Пары и предположительные виды показаны в раскрываемом списке, схемы четырёхстрочных фрагментов — над сеткой.
- В режиме «Серверный» для группирования применяется обученная на русском корпусе модель [RhymeTagger](https://github.com/versotym/rhymetagger) и фонетическая транскрипция eSpeak NG. Кандидаты (слова и короткие сочетания) отправляются на настроенный сервер; сам сервер не отправляет их сторонним сервисам и не сохраняет. Алгоритм адаптирует модель, изначально предназначенную для концов строк, к отдельным словам. В режиме «Локальный» группы определяются только браузерными эвристиками, без обращения к серверу. Результаты двух методов не смешиваются. Успешные результаты серверного анализа кэшируются в браузере по списку анализируемых слов и версии алгоритма (до 24 записей, объём около 700 тысяч символов); при повторном анализе тех же слов запрос на сервер не отправляется. Кэш хранит анализируемые слова на устройстве и может быть удалён вместе с данными сайта; если хранилище недоступно, кэш работает только в памяти вкладки. При изменении версии модели или обработки ударений разработчику необходимо обновить версию кэша в `src/rhymeCache.js`. Если сервер недоступен, пользователь может вручную переключиться на локальный режим. Метки видов рифм остаются эвристическими в обоих режимах. Ошибки и ложные совпадения возможны; объединение в цветовые группы выполняется по цепочке.
- Классификация видов рифм использует упрощённое сравнение написаний от ударной гласной и небольшую фонетическую нормализацию; это не полноценная транскрипция или словарь. Точная и неточные (ассонанс, диссонанс), богатая/бедная и составная рифмы определяются эвристически и могут быть ошибочны. Мужская, женская, дактилическая и гипердактилическая определяются по количеству слогов после ударения. Рифмовка анализируется группами по четыре непустые строки, с разделением по пустым строкам. Омонимию система не устанавливает — одинаковые слова предлагается проверить по смыслу вручную. Для многосложных слов необходимо расставить ударения; ударение на ё и в односложных словах (кроме служебных) предполагается. Составная рифма ограничена сочетанием ударного слова и до двух следующих безударных служебных слов. Цвета — связные группы: неточные совпадения могут объединяться по цепочке; при перекрытии клетка показывает первую группу. Для скорости анализируются первые 350 кандидатов и показываются первые 100 найденных пар.

Разбиение на слоги ориентировано на русский язык и носит автоматический, приблизительный характер. Метр не анализируется. Знаки препинания и пробелы присоединяются к соседней клетке; строки без гласных показаны как текст без клеток.

По умолчанию данные хранятся в localStorage браузера на текущем устройстве. Опционально можно включить синхронизацию с Google Диском. При очистке данных браузера они могут исчезнуть — скачивайте важные тексты.

## Синхронизация с Google Диском

Синхронизация необязательна. Без неё стихи по-прежнему сохраняются только в браузере. Подключение Arena к Google Диску для работы сайта не требуется: вход выполняется пользователем непосредственно в приложении.

1. В [Google Cloud Console](https://console.cloud.google.com/) создайте или выберите проект и включите Google Drive API.
2. Настройте экран OAuth consent: укажите данные приложения и, если приложение находится в режиме тестирования, добавьте свои Google-аккаунты как тестовых пользователей.
3. Создайте OAuth Client ID типа **Web application**. В «Authorized JavaScript origins» добавьте точный источник сайта (схема, домен и порт, без пути) — он показан в настройках синхронизации. Для разработки используйте, например, `http://localhost:5173`; для опубликованного сайта нужен HTTPS. Временный адрес предпросмотра может измениться и потребовать повторной настройки в Google Cloud.
4. В настройках сайта вставьте Client ID и нажмите «Подключить Google Диск». Разрешите доступ к данным приложения. Client secret в браузере не нужен и вводить его нельзя.

Используется область доступа `drive.appdata`: данные хранятся в скрытой папке данных приложения на Диске, а не среди обычных файлов. После входа приложение проверяет изменения при редактировании и примерно раз в 30 секунд. При первом подключении на другом устройстве непустые разные локальная и облачная версии считаются конфликтом. Если обе версии изменились после последней синхронизации, автоматическая запись останавливается; пользователь выбирает, какую версию сохранить. Слияния отдельных стихотворений и истории изменений нет. Скачайте важные стихи до разрешения конфликта.

Токен хранится только в памяти вкладки: после перезагрузки страницы или истечения срока действия потребуется снова войти. Client ID и данные стихов остаются в localStorage. Для входа и синхронизации нужны доступ к Google и сеть. Синхронизация проверяет облачную версию перед записью, но одновременные записи с разных устройств могут совпасть по времени; не редактируйте одну коллекцию одновременно и сохраняйте резервные копии.
